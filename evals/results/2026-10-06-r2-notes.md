## What changed

| Problem (judge M3, ux m3) | Change |
|---|---|
| The prompt's good example clues came back word for word on every park. "How many ways over the water can you find?" appeared 29 times in run `2026-10-06`. | The prompt describes what a good clue does and has no good example sentence. Its only full example clues are BAD ones, each with a reason. Each park gets a writing voice, picked by a hash of its name, from 6 voices. `validate.ts` drops a clue when at least 60% of its trigrams (and at least 3) come from one prompt example. It also drops a clue that nearly repeats another clue on the same pass. |
| Every park got the same fixed description per kind ("a roof on posts with tables underneath" on 4 parks). | `pool/park.ts` has 3 or 4 true facts per kind. Each park gets 2 of them, picked by a hash of park id + kind. The facts never use the kind's name words, digits or "map". |
| Wrong counts: Celebration's "Count the goals ... There are 25." The 25 is soccer fields. | Each Park Find carries `count: { of, n }`: the nouns the map count counts, and its number. A count clue must count the whole thing (fields, courts, seats, "places", "spots"), never a part (goals, hoops, nets), and must use the map's number. For Wild Finds, a number must be in the source with the same noun after it ("5 petals", not "5 spots" when the source says "5 cm"). |
| "How many ways over the water can you find? There is 1." | A count of 1 is now written "a bridge", with no number. A count clue needs a map count of 2 or more. |
| Generic clues: "Look for a tree with seeds or fruit." | A Wild Find clue needs at least one word, beyond generic ones, that is in its own source. A quote that is only the species' name proves nothing. Species whose summary has no looks-like word (colour, shape, size, part) leave the pool, because they can only get a generic clue. |
| Filler grown-up note: "Have fun exploring nature with your child!" | The model no longer writes `parentNote`. Code writes it from the pass's real items: which find to start with (easy, stays put, away from water if it can), which finds are near water, or which can move away. |
| More drops meant more second calls (3 of 6 in the first smoke). | The request asks for 1 spare item (n + 1). Code keeps the first n that pass every check and keeps each section's minimum. Unused spares are not counted as removed. |

## Two new eval metrics (`evals/score.ts`, in every results file from now on)

- **M10, cross-park repetition** (target 5% or less): the share of printed clues that contain a 5-word run, inside one sentence, which is also printed on passes of at least 2 other parks. Runs of the same park never count against each other.
- **M11, wrong counts** (target 0): printed clues with a wrong count, using the app's check plus an independent digit check against the map count for Park Finds. The results also show how many model items the check removed.

## Known gaps

- Gemma still writes some "a plant with seeds or fruit" clues, built only on the season sentence. They are now dropped, and that can cost a second call.
- Question-voice clues are sometimes not self-contained ("Is this a small white bird?"). The rule "each clue must make sense alone on paper" is only an instruction, with no code check.
- Find This Spot riddles still use the fixed kind description from `src/lib/spot/pick-target.ts` (Builder F's file), so a shelter's riddle is still "a roof on posts and tables". That file could use `factsFor()` from `pool/park.ts`.

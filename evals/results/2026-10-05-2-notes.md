# Notes on the 2026-10-05 S8b eval re-run (`2026-10-05-2.md`)

Numbers: `2026-10-05-2.md` (generated). Same 20 recorded parks, same age band (6-10), same models and runs as the
first run (`2026-10-05.md`). Run once as the frozen S8b result; nothing was re-run to improve a number.

## What changed in the app between the two runs
- **Name words (M3/M6):** `distinctiveWords` no longer turns stopwords (`and`, `the`, `of`...) into forbidden words,
  and OpenStreetMap feature names also drop generic place words (`park`, `trail`, `creek`...; when the place word is
  the answer, the feature kind's own name words still forbid it). Real giveaways are still caught ("makes honey" for a
  honey bee).
- **lookWhere:** a name word only in the "look where" hint now blanks the hint and keeps the item (the clue itself is
  fine); a name word in the clue still drops the item. The prompt says lookWhere must not use name words either, with
  a bad and a good example.
- **Retry keeps both answers:** when a second call is needed, the valid items of both calls are merged (inside the
  section limits) instead of keeping only the bigger answer.
- **Prompt size (M8):** at most n + 4 pool items per section are sent, and species summaries are cut to whole
  sentences up to 320 characters. Median Gemma prompt: about 2,590 tokens before, 1,902 after.
- **Answer budget:** `max_tokens` 1,200 for the pass call (measured answers: 348-696 tokens); gpt-oss keeps 2,000.
- **Quote rule:** the prompt asks for the shortest exact phrase, in one piece, with no "...".

## Why latency moved less than the prompt did
On the first run's 62 answered Gemma calls, a linear fit gives about 0.1 ms per prompt token and about 33 ms per
answer token: the time is the model writing its answer, not reading the prompt. Cutting the prompt by about a quarter
lowered cost a lot and latency a little; the median answer only went from 583 to 557 tokens. Reaching 10 s reliably
needs fewer answer tokens per pass (for example a smaller JSON shape) or two parallel calls (one per section). Both
change SPEC 6.1/6.2 and are left to the PM.

## New failure seen: text stuck onto every quote
In 3 of 56 Gemma answers, all for Trinity River Audubon Center (run 1 both calls, run 3 first call), every
`sourceQuote` had extra text appended, for example `"...across the park.专项parentNote: Help the child find a scenic overlook."`. 23 items failed
grounding that way (most of the drop from 99.2% to 91.6%); the Trinity run 1 pass had no valid clue left and showed
the model error copy, and in run 3 the retry then timed out. The smoke runs before this run showed the same glitch once ("covariance-parentNote: ..."). It
was not seen in the first run. A likely trigger is the new quote wording next to the parentNote rule; not tested yet.

## The WARNING line in the generated report
"52 runs sent a pool that differs from the scoring pool" is expected for this run: the app now sends a subset of the
pool (n + 4 per section), with the same ids and the same source texts as the scoring pool. The harness check was
changed after this run to test "subset of the scoring pool" instead of "equal".

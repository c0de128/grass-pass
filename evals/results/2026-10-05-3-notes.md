## What changed in the app between run 2 and this run
- **Glued-field quotes (bug):** in run 2, 3 of 56 Gemma answers (all Trinity River Audubon Center) had the next
  JSON field stuck onto every `sourceQuote` ("...across the park.专项parentNote: Help the child...",
  "...as well as TexasparentNote: ..."), so 23 correct quotes failed grounding and 2 passes ended as errors.
  `validate.ts` now cuts a quote that fails the substring check at a schema-field marker (a field name, a
  camelCase `...Note:` key or JSON punctuation residue). It also removes any glitch run in a non-Latin script and
  at most 2 junk words before the marker. Then it re-checks the result against the source. The kept text is always
  a real normalized substring of the source. A quote with no marker is never fuzzy-matched. Replayed offline on run
  2's saved answers, this repairs all 24 glued quotes and lifts run 2 from 44/51 to 46/51 complete passes (unit
  tests: `tests/unit/quote-repair.test.ts`).
- **Prompt:** `parentNote` is now stated as ONE line for the whole pass, not one per item. Keys come back in
  alphabetical order, so `sourceQuote` is the last key of each item. The glitch looked like the model starting a
  per-item parentNote there. The quote rule now says that the quote holds only the copied words.
- **Shorter answers (M7):** about 33 ms per answer token, so:
  - the model no longer writes `section` (code fills it from the pool item; a wrong section in an answer still
    drops the item);
  - `sourceQuote` asks for 3 to 8 words, never more than 12, and the request schema caps it at 90 characters
    (the SPEC 6.2 item schema still allows 240);
  - `parentNote` is under 10 words.
  - Median Gemma answer: 557 tokens in run 2, 456 now.

## Honest caveats
- **The glitch did not happen in this run.** 0 of 54 Gemma answers had a glued field, so the repair was never used
  live here. It is proven only on run 2's saved answers, offline. The 99.5% grounding comes from the model's own
  quotes: 2 of 423 failed, both real model mistakes.
- **M6 fails by 0.4 points:** 23 of 423 items used a word of their own answer before the filter: 15 in the clue (3.5%,
  under the SPEC's "clue contains the name" wording) and 8 only in the "look where" hint. Code drops every leaky clue
  and blanks every leaky hint, so no pass gives an answer away. Run 2 had 4.9%. This is within run-to-run noise, but
  it is reported as FAIL because the stricter count is the one we judge on.
- **The 2 remaining incomplete Gemma passes** (Klyde Warren run 1 and Frisco Commons run 2, 6 of 8 each) both lost two
  items to name leaks. A 6 of 8 pass does not trigger the retry, because SPEC 6.2 retries only when fewer than n-2
  survive. M3 counts n-1 as complete. Changing the retry rule is a SPEC decision, so it was left alone.
- Llama 4 Maverick is still far too slow for the default (43.0 s p50) and fails M3 (82.4%) and M6 (6.4%).
- Find This Spot is still not in the eval (no recorded geometry). On the live site a park with a landmark also gets
  a riddle in the same call, which adds a few dozen answer tokens.
